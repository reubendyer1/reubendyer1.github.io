Automated Dual Robotic Arm Device

Project overview

Led a student engineering team to design, manufacture and test a wheeled robotic device for the 2024 Warman competition. Two large articulated arms and gripping mechanisms were used to collect, carry and deposit six balls into a designated chute.

Mechanical design and fabrication

Personally designed more than 50 unique mechanical components in SolidWorks for 3D printing. The design incorporated articulated arm structures, gripping mechanisms and a mobile base, developed through prototyping and assembly.

  • Coordinated student team responsibilities throughout design, manufacturing and assembly.

Project 02 · Embedded systems

Real-Time FPGA Camera and Image Processing System

Multi-processor video acquisition, filtering and VGA output

DE10-Lite FPGANios IICVerilogSPISDRAMVGA

Project overview

Built a live image-processing system that acquires camera frames from an ESP32 camera, stores them in shared SDRAM, processes the image, and displays the result through VGA. The final architecture used three Nios II/f processors with separate responsibilities for SPI communication, image processing/display, and convolution assistance.

System architecture

Interrupt-based handshaking synchronised acquisition and processing, while a mutex protected shared SDRAM. A third processor was added to assist Sobel edge detection; its polling-based synchronisation limited the potential parallel speedup.

Image processing and user control

  • Implemented image flipping, blurring and Sobel edge detection.
  • Upgraded the system from 4-bit greyscale to 12-bit RGB444 display, converting camera RGB565 data.
  • Supported a full 320 × 240 image and a quad mode with four 160 × 120 sections.
  • Used accelerometer, keys and switches to change processing and display modes.

Project 03 · ECE4078 Robotics

Autonomous Sphero Robot Navigation and Control

Simulation, robot dynamics, feedback control, state estimation and learning-based navigation

PythonGymnasium-style interfacePyTorchPIDEKF frameworkOccupancy gridsPlanningSim-to-real

Project overview

Developed and investigated an autonomous navigation pipeline for a Sphero robot in simulated and physical maze environments. The project combined robot dynamics, control, localisation, map-based planning and machine learning, with the broader goal of reliable navigation in an unfamiliar race environment.

The simulator and real robot use a similar step-based interface. Observations include measured x/y position, heading, speed and a collision flag. Commands specify desired speed and heading angle, enabling algorithms to be evaluated in simulation before hardware trials.

Key technical components

Robot dynamics & motion control

Modelled state transitions for position, heading and speed. Coursework explores PID-based feedback control and the relationship between commanded motion and robot response.

State estimation

Created an EKF class structure with state prediction, measurement update, and process/measurement covariance matrices. The uploaded EKF file retains placeholder covariance and correction steps.

Mapping & path planning

Used maze occupancy grids to distinguish free cells from obstacles. The repository provides a waypoint-planning interface, but its uploaded planner returns a fixed example waypoint rather than a complete A* route.

Machine learning policy

Defined a PyTorch feed-forward policy with four state inputs, a 64-neuron hidden layer with ReLU, and two action outputs. A trained checkpoint and training pipeline were not present in this ZIP.

Collision detection

The robot interface exposes collision events and diagnostic values derived from acceleration changes, velocity drops and gyroscope spikes, supporting collision-aware navigation and debugging.

Simulation and real-world testing

Used a common robot/simulator API to support development and evaluation across virtual mazes and physical hardware, with attention to the sim-to-real gap.

Environment and navigation interface

  • Observations: x-position, y-position, heading, speed and collision indicator.
  • Actions: commanded speed and heading angle.
  • Diagnostics: odometry, acceleration, gyroscope, collision flags and commanded setpoints.
  • Planning environment: occupancy-grid maps, configurable goals and goal tolerances.
  • Project objective: integrate mapping, planning and control (or a trained policy) for an autonomous race against another robot in an unknown environment.
